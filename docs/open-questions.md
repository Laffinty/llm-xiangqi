## 开放风险

### RK-01

LLM 在棋盘空间推理上强依赖 ASCII 渲染，纯结构化反而更弱

- **状态：** `长期观察`（2026-10-11 降级）
- **原处置：** 由 W-04 A/B 消解；已用 `D-04` 保留 ASCII 兜底
- **2026-11 核查：** ASCII 盘与结构化 snapshot **同时存在**（`D-04` 的「结构化是增量」设计）。
  本项目**从未做过「移除 ASCII」的 A/B**，该假设至今既未验证也未推翻。
- **为何降级：** `PLAN-SPECTACLE-001` `P-17` 已证明本项目观感性指标
  **噪声 SD 是效应 SD 的 2 倍以上**，再做一次 A/B 只会得到「不可判定」。
  不占用后续工作量。

### RK-03

评测本身引入方差，**信噪比不足**，N 局加大也无法区分 A/B

- **状态：** `开放`（已与 RK-08 合并，见下）
- **原处置：** W-02 的反向守卫（逐字节可复现）+ 加大 N
- **2026-11 核查（`PLAN-SPECTACLE-001` `P-17`）：** 问题比「样本量不足」更严重——
  - `temperature=0.0` 下 **API 仍非确定性**：同 commit、同 seed、同局面集、同温度，
    **完全相同的命令**跑两遍，**5/5 局走法逐手不同**
  - 均值型观感性指标的**噪声 SD 是效应 SD 的 2 倍以上**
    （最长静默 6.27 vs 2.74；闷摆 5.61 vs 3.35；棋风摇摆 7.25 vs 2.24）
  - **结论：扩样本只会把噪声缩小 √n，噪声/效应比不变，信号浮不出来。**
    「加大 N」这条旧处置**已被证伪**，不再是出路。

### RK-04

**决策契约在 Anthropic 协议路径上形状不兼容（不是「未实测」，是已查明必然失败）**

- **状态：** `已查明`（2026-11-11 静态核查，无需网络即可定论）
- **原处置：** W-01 完成后立即实测 —— **已由静态核查取代**

**核查结论（读代码即可确定）**：

1. `decision_contract.build_tool()` 产出的是**纯 OpenAI 形状**：
   ```json
   {"type": "function", "function": {"name": "move_decision", "strict": true, ...}}
   ```
2. Anthropic 的 `tools` 要求**扁平列表** `[{name, description, input_schema}]`，
   **没有 `type: "function"` 外层，也没有 `strict` 字段**。
3. `anthropic_base_adapter.py:132` 只做 `params["tools"] = tools` —— **原样透传**，
   既不转换形状，也不剥离 `strict`（源码中 `tool_choice` / `strict` 出现 0 次）。

**因此：即使拿到 `ANTHROPIC_API_KEY`，决策契约在这条路径上也会因形状不兼容而失败。**
本机当前也确实无该密钥（环境变量未设，桌面 `TEST_API.txt` 只有 deepseek / mimo），
`anthropic` SDK 1.8.0 已安装但从未被调用。

**另注**：`tests/test_protocol_sequence.py` 里的 `_to_anthropic()` 是**复刻实现**，
只验证「并行 `tool_result` 合并为单条 user 消息」这一条协议形状，
**不覆盖 tools 形状转换**，且与真实适配器存在漂移风险（代码复制一遍，
真实逻辑改了测试不会发现）。

**修复方向（未做，需单独裁决）**：在 `AnthropicCompatibleAdapter` 内把契约
转换为 Anthropic 原生形状，并剥离 `strict`。属改 `src/`，超出观测范围。

### RK-05

Skill 拆分把 doctrine 切碎后，模型跨 skill 推理出现断层

- **状态：** `开放`（2026-11 降优先级）
- **原处置：** 由 W-05 的 A/B 消解
- **2026-11 核查：** `PLAN-SPECTACLE-001` `P-02` 把三个中局 skill **合并为一个**后，
  **中局只激活 1 个 skill**，「跨 skill 推理」在中局**已不成立**。
  剩余多激活场景仅「残局 + 被将军 + 重复」三合一。
- **为何不补观测**：报告未记录每回合 `active_skills`，离线无法判定；
  补采集需改 3 个 `src/` 文件 + 跑 1~2 局（约 20 分钟 API），
  而结论大概率是「未观察到断层」。**投入产出比不足，记为已知盲区。**

### RK-06

渐进披露反而增加往返（读 skill → 用 skill 多一轮 LLM 调用）

- **状态：** `已消解`（2026-11-11 实测）
- **原处置：** W-05 需统计 LLM 调用次数，不只看胜率 —— **已执行**
- **判据：** `llm_calls / decisions`。若存在「读 skill → 用 skill」两轮调用，该比值 > 1.0。

| 报告 | 样本 | min | max | mean |
|---|---|---|---|---|
| `eval-baseline.json` | 14 | 1.00 | 1.00 | **1.00** |
| `eval-attack-baseline.json` | 10 | 1.00 | 1.05 | 1.01 |
| `eval-attack-before.json`（改造前） | 10 | 1.00 | 1.05 | 1.02 |

**结论：每决策恰好一次 LLM 调用，渐进披露不引入额外往返。**
1.05 的少量超出来自 `max_retries` 重试——**「改造前」的报告同样出现 1.02~1.05 可作对照**，
证明与渐进披露无关。
- **守卫**：`tests/test_no_llm_roundtrip.py`（2 项）锁定
  `llm_calls <= decisions * 1.1`，并要求基线锚点**恰好** 1.00——
  若基线本身开始漂移，说明报告统计口径变了，本条结论需重做。

### RK-07

40 回合预算下开局/中局不收敛（4 局全撞上限），残局与被将军局面可收敛

- **状态：** `开放`
- **原处置：** `F-023`：残局 20 手、被将军 34 手分胜负；开局/中局需更长预算才能观测。W-03 落地后需重测是否改善
- **部分缓解（2026-10-11）**：`PLAN-SPECTACLE-001` `P-13` 发现——用**子力充足、双方有攻防手段**的局面
  （`tests/eval/cases_attack.json`）时首次出现自然终局，而旧局面集里的死局残局**本来就不可能终局**。
  即 `RK-07` 的部分成因是**评测集本身的死局**，不全是「LLM 不收敛」。

### RK-08

观感性指标**无法量化验证 doctrine 效果**（信噪比不足）

- **状态：** `开放` —— **已与 RK-03 合并**，两者实为同一问题的两种说法
  （RK-03 说「样本量不足」，RK-08 说「信噪比不足」；`P-17` 证明后者）
- **实测证据**（`PLAN-SPECTACLE-001` `P-17`）：同 commit、同 seed、同局面集、同温度，
  **完全相同的命令**跑两遍，**5/5 局走法逐手不同**——`temperature=0.0` **并非确定性**
  （MoE 路由 / 批处理浮点非结合 / 服务端漂移）。
  均值型观感性指标的噪声 SD 是效应 SD 的 **2 倍以上**（最长静默 6.27 vs 2.74）。
- **含义**：把 n 从 5 扩到 20 只会把噪声缩小 2 倍，**噪声/效应比不变，信号仍浮不出来**。
  当前指标体系无法回答「观赏性改造是否有效」。
- **已落地缓解**（`P-18`）：新增二值护栏指标 `stuck_game_rate`
  （该局是否出现 ≥8 手连续无吃无将）——**同配置两次跑完全一致**（均 0.4），
  可可靠判「是否退化到不可看」，但**不能**度量「提升了多少」。
- **已裁决（2026-11-11）**：观赏性提升**不做人工观感评估**（业主裁定），
  **不再追加观感性 A/B**——继续投 API 额度属沉没成本。
  量化指标已重新定位为**护栏**而非验收标准。
  唯一实际证据是人工试看反馈：**「有所进步，但不多」**。

## 待决策

### C. 真实对局局面集要不要纳入常规评测

**背景**：2026-10-10 的 Web 对局 13 手自然终局（红方将死胜），
而冻结集 `cases.json` 的 7 个局面全是合成局面，实测中**从未产生自然终局**——
这正是 `RK-07` 的成因之一。

**已做**：该局已复盘并存为 `tests/eval/cases_real.json`（7 个红方走棋局面，
终局 FEN 保留在 `source_game`）。用 `--cases-file` 选择。

**未决**：是否把它作为**常规**评测集。理由是合成局面与真实分布有系统差异，
只在合成集上评估可能高估改动效果；但换成真实集又会让历史基线全部失效。

**约束**：`--compare` 两侧必须用同一套局面集；报告 `meta.cases_file` 会记录。

### A. 是否启用方案 A（真实棋力观测）

**问题**：40 回合预算下开局/中局对局不收敛（`RK-07`），胜负不可观测。

- **方案 A** —— 提高回合上限至对局能自然终局。代价：每局从 ~4 分钟涨到 20+ 分钟，
  且需每组 30+ 局才能区分 A/B，数十小时量级。
- **方案 B** —— 永久以「激活正确性 + 成本 + 合法率」为验收标准。
  **已采纳**（2026-10-09），落地见 `F-030`：激活一致性实测 1.0。

**现状**：B 已生效。A 保留为未选项，需要时再启用。

### B. `W-04`（BoardSnapshot）是否做受控 A/B

**问题**：它作为激活一致性的**输入**已被验证有效（一致性 1.0、空激活率 0.0），
但它**本身**是否带来额外价值，尚未单独测量——当前每次都会启用。

**做法**：给快照加开关，关掉跑一次对照。

**现状**：可选，成本低（每手约 +0.3% token 的反向）。不做也不阻塞任何东西。
