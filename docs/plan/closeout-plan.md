## §1 核查结论（`已核实`，2026-10-11）

### 1.1 RK-06「渐进披露增加往返」→ **可判定，结论：已消解**

**判据**：`llm_calls / decisions`。若渐进披露导致「读 skill → 用 skill」两轮调用，
该比值应 > 1.0。

实测三份报告（`已核实`）：

| 报告 | 样本 | min | max | mean |
|---|---|---|---|---|
| `eval-baseline.json` | 14 | 1.00 | 1.00 | **1.00** |
| `eval-attack-baseline.json` | 10 | 1.00 | 1.05 | **1.01** |
| `eval-attack-before.json` | 10 | 1.00 | 1.05 | **1.02** |

**结论：每决策恰好一次 LLM 调用**，不存在额外往返。
1.05 的少量超出来自 `max_retries` 的重试（`agent_config.yaml` 有 `max_retries: 3`），
**与渐进披露无关**——「改造前」的 `eval-attack-before.json` 同样出现 1.05，可作对照。

> 建议动作：把该结论写回 `open-questions.md`，`RK-06` 标记 `已消解`。
> 附一条守卫测试锁定 `llm_calls <= decisions * 1.1`，防止将来重构引入往返。

### 1.2 RK-01「纯结构化反而更弱」→ **部分消解，**建议降级为长期观察项**

### 1.3 RK-07「40 回合不收敛」→ **依然成立**，且**本轮不解决**

## §2 执行计划（**按优先级，均需拍板后才动手**）

### P-C1 测通 Anthropic 协议路径 —— 优先级 **1**

**为什么最该做**：唯一一个「明确知道有坑、但从没踩过」的项；且它是纯验证工作，
不改被测系统（`skills/`/`prompts/`/`config/` 全不动），风险最低。

**改动面**：

| 文件 | 改动 |
|---|---|
| `tests/eval/providers.py` | `PROVIDERS` 增加 `anthropic` 条目（`env: ANTHROPIC_API_KEY`） |
| `tests/eval/README.md` | 补一条 `--provider` 用法说明 |

**不动**：`src/` 下任何文件。特别地，**不修改 `tests/test_protocol_sequence.py` 里
那个复刻的 `_to_anthropic()`**——它作为「协议形状的独立第二实现」保留，
与真实适配器互为交叉验证。

**验收命令**：

```powershell
python -m tests.eval.run --probe --api-file <密钥文件>
```

**通过判据**（三条全绿才算）：

1. `anthropic` 出现在 probe 输出里，且 `chat_ok: true`
2. `has_thought` / `tool_call_turns` 有合理取值（不是恒为 `None`/`0`）
3. **若**具备密钥且网络可达，跑一局 `--only-category middlegame`，
   要求 `move_quality.*.illegal_rate == 0`（与 OpenAI 兼容路径同标准）

**反向守卫**：跑完后确认**没有**因 `tool_choice: required` 而失败回落到 `auto`——
若回落，`F-013` 的结论在这条路径上不成立，需记录。

**若失败**：不修改适配器去迁就，而是把具体报错写回 `open-questions.md` 的 `RK-04`，
作为已知事实保留。

**成本**：仅 probe 的话约 1 次 API 调用；若跑一局约 30 分钟 + 额度。

**前置条件**：需要 `ANTHROPIC_API_KEY`。**若没有密钥，本项降级为「只查 SDK 是否安装」，
并把 RK-04 标注为「阻塞：无密钥」**。
