`D-01`~`D-10` / `W-00`~`W-08` 已归档且不得复用，本文档另起前缀**：

## §1 观测事实

### E-01 现有 5 个 SKILL 全部是「棋艺教条」，无一涉及观赏性 —— `已核实`

```
rg -n "^description:" skills -A2
```

`opening-development` / `middlegame-tactics` / `endgame-technique` / `check-defense` /
`repetition-management` 的 frontmatter 与正文，**全部在讲「怎么下对」**：
出子次序、目标设定、子力价值、解将优先级、重复局面识别。

**没有任何一条涉及**：这盘棋好不好看、该不该制造张力、该不该兑子简化、弃子的取舍。

**这条是本文档的出发点**：现有 SKILL 体系在优化「棋力」，而观赏性是一个**未被建模的维度**。

### E-02 `base.md` 已有棋风设定，但因措辞过软而不可执行 —— `已核实`

`prompts/base.md`「你的棋风特质」列出进攻型 / 稳健型 / 灵活型 / 防守反击型，句尾是：

> 自然展现以下一种或多种棋风，**不要僵化执行**

`config/agent1_config.yaml` 与 `agent2_config.yaml` 均未指定任何棋风字段，两边拿到**完全相同**的
棋风段。

**问题**：同一段话发给两个 agent，双方必然收敛到同一种「中庸棋」。这与 `RK-05`
（跨 skill 推理断层）不同——这是**两边同质化**，是一盘棋无趣的直接来源。

### E-03 评测报告已含完整 `move_history`，观赏性指标可离线重放 —— `已核实`

```
$j = Get-Content -Raw docs/eval-baseline.json | ConvertFrom-Json
$j.raw[0].move_history
```

原始输出（首局前 12 手）：

```

```

`raw[i]` 字段清单：
`aborted / black / case_id / category / elapsed_sec / move_history / move_quality /
moves_played / red / result / result_reason / starting_fen / stats / turn_count`

**这是本方案最重要的可行性事实**：吃子数、将军数、兑子数、走子重复度、每步的
是否新子力接触，**全部可由 `starting_fen` + `move_history` 用 `RefereeEngine` 纯离线重放得出**，
不消耗任何 API。基线 `docs/eval-baseline.json` 与 `eval-after-w03/w04/w05/w05b.json` 均可直接回放。

### E-04 「趣味性」在象棋引擎界有既成的一等参数 —— `已核实`

UCCI 3.0（中国象棋通用引擎协议 v3.0，`xqbase.com/protocol/cchess_ucci.htm`）第 (16)(17) 项原文：

> (16) `randomness(combo)`，设定随机性系数，和 `pruning` 一样有四种设定，一般都设为 `none`，
> 以保证引擎走出它认为最好的着法，**但为了增强走棋的趣味性，可以把这个参数调高，
> 允许引擎走出它认为不是最好的着法，以丰富走棋的样式**；
> (17) `style(combo)`，设定下棋的风格，通常有 `solid`(保守)、`normal`(均衡)和 `risky`(冒进)三种。

**这是对「棋力 vs 观赏性」取舍最权威、最直接的表述**：引擎界把「允许走次优着以增加趣味」
做成了一个正式参数，并且明确默认 `none`。本项目的 SKILL 改造，本质是把这个已被承认的取舍
**用自然语言落到 LLM 上**。

### E-05 `randomness` 的取舍方向与 AlphaZero 的多样性机制同源 —— `已核实`

AlphaZero（Silver et al., 2017）动作选择：self-play 前 30 手 `τ=1`（按访问次数比例采样），
之后 `τ→0`；并在搜索树根部混入 Dirichlet 噪声 `ε=0.25`、`α=0.3`（与国际象棋合法着法数成反比）。
推理阶段则完全贪心、无噪声。

**要点**：它并非全程随机，而是**把随机性集中在开局（探索期），中后盘回归确定性（收敛期）**。

这与本项目的阶段路由天然契合：现有 router 已按 `board_phase` 激活 SKILL，
意味着「开局更随机、中局更确定」可以**由激活条件天然表达**，不需要改代码。

### E-06 长打类终局是「最难看也最不划算」的终局，且规则上单方长将直接判负 —— `已核实`

《象棋竞赛规则（2020 版）》第 23 条（`cnchess.net`）原文：

> 23.5.1 单方「长将」立即判负。
> 23.4 长杀长捉的特殊规定：如果一方在**三个或三个以上**点上，连续以将杀捉的交替重复着法达
> **九个回合**，即使未形成三次重复的待判局面，经一方提出，可按待判局面的有关规定进行裁决。
> 23.2 循环计算规则：在判断是否已达「重复局面」时，即形成循环之首着（通常为「外来点」）应计算在内。
> **如首着为「吃子」应予扣除，不计算在循环反复之内。**

允许着法为四类非攻击行为：**兑、献、拦、跟**；其余（长将、长杀、长捉、一将一杀等）属禁止着法。
一方禁止而另一方允许 → **禁止方不变判负**；双方均禁止（不含单方长将）→ 不变判和。

**与观赏性的关系**：长打导致的和棋是**纯粹的观赏性灾难**——双方毫无推进地互相循环几十手。
现有 `repetition-management` 只说了「重复局面按棋盘判定」，**未区分禁止着法与允许着法**，
模型无法判断「我这手将是在主动求和还是在送判负」。这是一条**可证伪的规则知识缺口**。

### E-07 名局的共同结构是「弃子攻杀」而非「稳走」—— `已核实`

多篇名局赏析（胡荣华 1984 弃炮弃车「虎口掏心」；钟珍 1920 年代弃车弃马双炮绝杀；
1956 沈之一弃车攻杀）共同点，原始表述：

> 这一连串的弃子，如同一道闪电划破夜空……其真正目的并非鲁莽，而是为了：**撕开防线**、
> **解除牵制**、**直捣黄龙**。
> 弃马引离黑车，弃车调开黑炮……舍弃大子，他压缩黑将活动空间。

象棋公社对「名局」的定义亦为：**由一步石破天惊的「神来之笔」所定义**。

**要点**：观赏性来自**目的明确的子力投入**，不来自随机性本身。现有 `middlegame-tactics` 写了
「`弃X` —— 只在有明确后续收益时使用」，但这是**禁令**（别乱弃），不是**许可**（何时该主动弃）。

### E-08 国际象棋界对「精彩着法」有可复用的判定条件 —— `已核实`

多个平台与论文对 brilliant move 的定义高度一致，核心三条（Chess.com / FireChess / chessbio）：

1. **必须是弃子**——「No sacrifice, no Brilliant」。
2. **必须成立**——引擎认可，弃后不吃亏；被反驳的投机弃子不得分。
3. **必须有选择**——安全着法摆在桌面上而你选了激烈的。**被迫的弃子只算「Great」，不算「Brilliant」**。

另有一条常被忽略的辅助判据：**弃子带将军是最高频的精彩模式**，因为将军把对手的应手压到极少，
使弃子变得可计算。

**可迁移性**：这三条与象棋名局的赏析口径一致（钟珍/胡荣华的弃子都是在大量安全着法中主动选择），
因此可直接作为 SKILL 里「主动弃子」的**判据**，而非泛泛的「要有进取心」。

## §2 方案裁决

> 以下均为 `建议`，尚未 `已裁决`。裁决权在业主。

### S-01 观赏性不是「让模型乱走」，而是「在有安全着法时主动选不安全的那个」—— `建议`

由 `E-04` + `E-08` 共同支撑：

- UCCI 说 `randomness` 的作用是「**允许引擎走出它认为不是最好的着法**」——它不改变搜索，
  只改变**选择**。这恰好是 SKILL（知识层）能做的事，也恰好是引擎搜索层做不到的事。
- Brilliant move 的第 3 条「必须是有选择时的主动选择」，把这件事的判据钉死了。

**因此本轮的全部改造应指向一个动作**：让模型在「安全且正确」与「激烈且成立」之间，
**有一个明确的、可执行的、自称的选择规则**。

**排除的替代方案**：直接调高 `temperature`。`E-03` 已固定评测温度为 0，且调高温度会让
`RK-03`（评测方差）雪上加霜，且无法控制「随机落在哪一步」——它不产生戏剧性，只产生噪声。

### S-02 新增 3 个 SKILL，而不是改写现有 5 个 —— `建议`

现有 5 个 SKILL 的职责边界清晰，且 `F-030` 实测激活一致性 1.0、空激活率 0.0。
**改写它们会同时触碰这两项已验证的成果。** 因此采用增量：

| 新 SKILL | 激活条件（`when` DSL） | 解决什么 |
|---|---|---|
| `game-narrative`（对局主题） | 恒真（常驻） | 双方各自锁定一个棋风目标，中局前不换 |
| `sac-culture`（弃子文化） | `board_phase in [middlegame, endgame]` | 主动弃子的**许可 + 判据**（`E-08` 三条） |
| `tempo-drama`（节奏与张力） | `board_phase eq middlegame` | 禁止无意义来回；制造将军/吃子/兑子的节奏 |

**并且**：`opening-development` 保持不动，但 `references/aphorisms.md` 追加「求变类」口诀。

### S-03 每条 doctrine 必须自带可数指标，否则不得写入 —— `建议`

这是从本仓库历史教训直接推导的：`docs/history/skill-mode-design.md` 反复出现
「加了一条禁令但没加指标 → 无法证伪 → 沦为散文」。**观感性尤其如此**——「更精彩」如果没有
计数定义，等于没写。

因此 `P-02` 的每个 SKILL 条文都必须能对应到 §3 的至少一个指标，否则不进 SKILL.md。

### S-04 观赏性与合法性的冲突方向已裁决：合法性优先 —— `建议`

`illegal_rate` / `parse_failures` 是既有硬门禁（`tests/eval/README.md` 门禁表）。
本轮**不得**让这两个指标上升。`E-04` 的 `randomness` 是引擎内部参数，
不改变合法性；SKILL 层同样必须遵守：**只在合法走步枚举内做选择**（`D-05` 的 enum 契约不变）。

## §3 观测指标（先度量，后改造）

**沿用 `D-08`「度量必须前置」**。以下指标全部由 `starting_fen` + `move_history`
用 `RefereeEngine` 离线重放得出（依据 `E-03`），**零 API 成本**。

### 3.1 指标定义

| 指标 | 定义 | 期望方向 | 对应 SKILL |
|---|---|---|---|
| `tactic_rate` | 含吃子或将军的着法占比 | ↑（**但设上限**，见 S-05） | `tempo-drama` |
| `quiet_streak_max` | 连续无吃子无将军的最长手数 | ↓ | `tempo-drama` |
| `move_repeat_rate` | 与本方此前走法集合重复的比例（同子同向） | ↓ | `tempo-drama` |
| `sac_count` | 弃子着法数（主动送子且非被迫应将） | ↑（≥0） | `sac-culture` |
| `sac_sound_rate` | 弃子中 N 步内不亏子力的比例 | ↑ | `sac-culture` |
| `style_drift_count` | 棋风目标在局中切换的次数 | ↓ | `game-narrative` |
| `long_chase_turns` | 进入长打/重复循环的回合数 | ↓ | `check-defense` / `repetition-management` |

### 3.2 反向守卫

- `illegal_rate` 不得上升
- `parse_failures` 不得上升
- `text_only_ratio` 不得上升
- 每手平均 token 增幅 ≤ **+12%**（基线 `F-029` 显示 skill 模式已省输入 26%，本轮不得吃掉全部余量）

### 3.3 判读规则（防止误判）

**本节是本方案最容易出错的地方，故显式规定：**

1. **单局差异一律不判读。** `RK-03` 已确认评测本身引入方差。任一指标需 **≥7 局**均值。
2. **`tactic_rate` 不是越高越好。** 若其值 > 0.55，应判为**过火**（双方互将军形成噪音），
   而非「更好」。此判据**必须**写进门禁，否则优化会朝反方向跑。
3. **基线缺指标 → 判「无法判定」并退出码 1。** 沿用 `tests/eval/README.md` 既有语义，
   **不把「没测过」显示成「通过」**。
4. **A/B 两侧必须同一 `--seed` 与同一 `--cases-file`。**

超出本轮非目标。

## §5 风险

### T-01 观赏性与棋力直接冲突 —— `开放`

`E-04` 已明说 `randomness` 的作用是「走出它认为不是最好的着法」——**它必然降低棋力**。
本轮接受了这一取舍（`S-01`），但**必须显式承认**：

> 若将来要用棋力验收，`sac_rate` 与 `illegal_rate` 不可同时作为目标。

**缓解**：本轮不门禁棋力（见 P-05 非目标）。

### T-02 `sac-culture` 可能诱发「为了观赏而弃子」的亏损棋 —— `开放`

最危险的失效模式：**模型学会「弃子 = 精彩」，无脑弃子送车**。

**缓解**：强制 `E-08` 第 2 条「弃子须成立」，并在 `sac_sound_rate` 上设反向守卫。
若 `sac_count` 上升而 `sac_sound_rate` 下降 → **判为失败**，不得判为「观赏性提升」。

### T-03 双方同时激进导致对局更难看 —— `开放`

若 `S-04` 未落实（棋风未硬绑定，见 P-04 挂起），`game-narrative` 只是软文，
**两个 agent 会同化为同一种激进**。

**缓解**：§3.1 的 `style_drift_count` 只能测「个体是否摇摆」，**测不了「双方是否同质」**。
这是一个**已知的指标盲区**，需在 §7 补充说明。

### T-04 「可回放」依赖 `move_history` 完整 —— `已消解`

`E-03` 已核实字段存在且完整。基线 `aborted: true` 的对局需排除或截断到合法前缀。

## §7 已知盲区（如实记录）

1. **`style_drift_count` 测不了双方同质化。** 双方都用同一段 `base.md` 棋风时，
   各自都不「漂移」，指标为 0，但一盘棋仍然无趣。真正的解法是 `P-04`（硬绑定不同棋风），
   而 `P-04` 当前挂起。**在 P-04 落地前，`game-narrative` 的实际收益无法被现有指标完整捕捉。**
2. **无引擎评估。** 本轮全程不调 Pikafish，因此 `sac_sound_rate` 只能用
   「N 步内有无丢子」这个**粗糙代理**近似，不是真正的引擎认可。真正的「须成立」需引擎复核。
3. **无人类观感评分。** 全部指标是代理指标，**不等于「好看」**。最终仍需业主本人看几局观感。
